## 上传失败弹窗 + EasyImage 状态码对照

- 用户上传报 code 201，状态栏文案太隐晦 → 改成弹窗展示。
- **查证 EasyImage 官方 docs/常见状态代码.md（关键）**：201=服务端已关闭 API 上传；202=游客限制/Token 错误；203=Token 过期；204=未收到文件；205=IP 黑白名单；400=文件问题；401=需登录；403=签名错误；406=非法文件。（删除类：206 部分失败；登录类 200/400）
- Rust `upload_easyimage`：不再用 error_for_status（保留服务端 body）；非 JSON 响应带 300 字原文片段；message 为空时按官方码表兜底中文原因；错误串统一带 code + HTTP 状态。
- 前端 `showUploadError(detail, {file, failures})`：openSheet 弹窗，展示原始错误（`.error-detail` 等宽可复制）+ 按 code 给排查建议（images.errHint.*，覆盖 201/202/203/204/205/400/401/403/406/other）+ 复制错误详情/关闭；三处上传入口（粘贴自动、右键单图、批量）全部改为弹窗；批量失败列出失败文件名。
- 经验：EasyImage 的 201 不是"文件写入失败"，而是后台 API 开关没开——排查这类"隐晦 code"必须先查官方状态码文档，不能凭 HTTP 语义猜。
- 验证：vite build 通过（21.90s）；cargo check 通过。
- 注意：cargo check 曾因 target/debug/.cargo-build-lock 被占用（用户开着 dev 版）失败，需重试。
